## 1. Что получилось в итоге

Сайт из шести типов страниц:

| Адрес | Страница |
|---|---|
| `/` | Главная: приветствие, избранные проекты, последние статьи |
| `/projects/` | Все проекты с фильтром по технологиям |
| `/projects/<slug>/` | Страница одного проекта |
| `/blog/` | Список статей |
| `/blog/<slug>/` | Одна статья |
| `/about/` | Обо мне: навыки и путь |
| `/contact/` | Контакты |
| `/sitemap.xml`, `/robots.txt` | Служебные файлы для поисковиков |

Особенности:
- тёмно-синий фон с золотыми акцентами и градиентами;
- адаптивная вёрстка (на телефоне появляется меню-«бургер»);
- проекты и статьи добавляются **без программирования**, через текстовые файлы;
- сайт можно собрать в обычный HTML и бесплатно опубликовать.

## 2. Используемые технологии

| Технология | Зачем |
|---|---|
| **Python 3.11+** | язык, на котором написан сервер |
| **Flask** | веб-фреймворк: принимает запрос → отдаёт HTML-страницу |
| **Jinja2** | шаблонизатор (входит во Flask): HTML с переменными и циклами |
| **PyYAML** | читает файл с проектами `projects.yaml` |
| **Markdown + Pygments** | превращают `.md` в HTML и подсвечивают код |
| **python-frontmatter** | читает «шапку» статьи (заголовок, дата) |
| **Frozen-Flask** | превращает сайт в набор статических HTML-файлов |
| **pytest** | автоматические тесты |
| **HTML / CSS / JS** | внешний вид и интерактивность |

**Почему Flask, а не Django?** Для портфолио не нужны база данных, пользователи и админка.
Flask проще: весь сайт — это примерно 150 строк Python.

## Шаг 2. Настройки — `config.py`

Все «личные» данные собраны в одном классе:

```python
class Config:
    SITE_NAME = "Xagan6_9"
    SITE_TAGLINE = "Python-разработчик"
    SOCIAL = {"GitHub": "...", "Telegram": "...", "Email": "mailto:..."}
    SKILLS = {"Языки": ["Python", ...], ...}
```

**Почему так?** Если имя или ссылка встречаются на 5 страницах, менять их нужно в одном месте.

`SECRET_KEY` и `SITE_URL` читаются из переменных окружения (`os.environ.get`):
секреты нельзя хранить в коде, который выкладывается на GitHub.

## Шаг 3. Фабрика приложения — `app/__init__.py`

```python
def create_app(config_class=Config):
    app = Flask(__name__)
    app.config.from_object(config_class)

    from .routes import bp
    app.register_blueprint(bp)
    ...
    return app
```

Разбор:
- **Фабрика приложения** — функция, которая создаёт приложение. Это стандартный приём во Flask:
  в тестах можно создать приложение с другими настройками.
- **Blueprint** (`bp`) — «набор маршрутов». Мы подключаем его к приложению.
  Из-за него имена страниц пишутся с префиксом: `main.index`, `main.projects`.
- **context_processor** добавляет переменные (`site_name`, `social`, `current_year`) во **все** шаблоны сразу.
- **template_filter `ru_date`** — свой фильтр, который выводит дату по-русски: `9 ноября 2026`.
  В шаблоне: `{{ post.date | ru_date }}`.
- **errorhandler(404)** показывает красивую страницу вместо стандартной ошибки.

`run.py` просто вызывает фабрику и запускает сервер:
```python
app = create_app()
app.run(debug=True)   # debug=True — автоперезапуск при изменении кода и подробные ошибки
```

## Шаг 4. Контент: YAML и Markdown

### 4.1. Проекты — `content/projects.yaml`
YAML — простой формат для данных. Каждый проект — элемент списка (начинается с `-`):

```yaml
- slug: weather-bot              # адрес страницы: /projects/weather-bot/
  title: Telegram-бот погоды
  summary: Короткое описание для карточки.
  description: |                 # «|» — многострочный текст, можно писать Markdown
    ## Задача
    ...
  stack: [Python, aiogram]       # теги технологий
  image: img/weather-bot.svg     # картинка из app/static/
  github: https://github.com/...
  demo: https://...              # необязательно
  featured: true                 # показывать на главной?
  date: 2025-09-01               # для сортировки (новые — первыми)
```

> ⚠️ В YAML важны **отступы** (пробелы, не Tab!). Если сайт перестал открываться после правки — проверьте отступы.

### 4.2. Статьи — `content/posts/*.md`
Каждая статья — отдельный файл. Сверху «шапка» (front matter) между `---`:

```markdown
---
title: Заголовок статьи
date: 2026-11-09
summary: Краткое описание
tags: [python]
draft: true        # необязательно: черновики не показываются
---

Текст статьи в **Markdown**.
```

Имя файла становится адресом: `python-tips.md` → `/blog/python-tips/`.

### 4.3. Код загрузки — `app/content.py`

```python
@lru_cache
def get_projects():
    with open(CONTENT_DIR / "projects.yaml", encoding="utf-8") as f:
        projects = yaml.safe_load(f) or []
    for p in projects:
        p["description_html"] = render_md(p.get("description", ""))
    return sorted(projects, key=lambda p: p["date"], reverse=True)
```

- `yaml.safe_load` превращает YAML в список словарей Python;
- `render_md` превращает Markdown в HTML (с таблицами и подсветкой кода);
- `sorted(..., reverse=True)` ставит новые проекты первыми;
- `@lru_cache` запоминает результат, чтобы не читать файл при каждом запросе.
  **Следствие:** после правки YAML перезапустите сервер (Ctrl+C → `python run.py`).

`get_project(slug)` ищет один проект: `next(...)` возвращает первый подходящий или `None`.
`get_all_tags()` собирает все технологии без повторов (через множество `{}`) для фильтра.

## Шаг 5. Маршруты — `routes.py`

Маршрут связывает адрес с функцией, которая возвращает страницу:

```python
@bp.route("/projects/<slug>/")
def project(slug):
    item = get_project(slug) or abort(404)
    return render_template("project.html", project=item)
```

- `<slug>` — переменная часть адреса, Flask передаёт её в функцию;
- `or abort(404)` — если проекта нет, показать страницу 404;
- `render_template` берёт шаблон и подставляет в него данные.

**Почему адреса заканчиваются на `/`?** При статической сборке `/projects/` превращается
в файл `projects/index.html`. Такой адрес открывается на любом хостинге.

## Шаг 6. Шаблоны Jinja2

### 6.1. Наследование
`base.html` — общий каркас (шапка, меню, подвал). В нём есть «дыры» — блоки:

```html
<title>{% block title %}{{ site_name }}{% endblock %}</title>
<main class="container">
  {% block content %}{% endblock %}
</main>
```

Остальные страницы **наследуют** каркас и заполняют блоки:

```html
{% extends "base.html" %}
{% block title %}Проекты — {{ site_name }}{% endblock %}
{% block content %}
  ...содержимое страницы...
{% endblock %}
```

Плюс: меню и подвал написаны один раз.

### 6.2. Синтаксис Jinja2
| Конструкция | Что делает |
|---|---|
| `{{ переменная }}` | вывести значение |
| `{% for p in projects %}...{% endfor %}` | цикл |
| `{% if posts %}...{% endif %}` | условие |
| `{{ value \| фильтр }}` | применить фильтр (`join`, `safe`, `ru_date`) |
| `{{ url_for('main.blog') }}` | получить адрес страницы по имени |
| `{{ url_for('static', filename='css/style.css') }}` | адрес статического файла |

### 6.3. Макросы — `_macros.html`
Макрос — это «функция» в шаблоне. Карточка проекта нужна на главной и на странице проектов,
поэтому она вынесена в макрос:

```html
{% macro project_card(p) %}
<article class="card">...</article>
{% endmacro %}
```
Использование: `{% from "_macros.html" import project_card %}` → `{{ project_card(p) }}`.

### 6.4. Подсветка активного пункта меню
```html
{% set ep = request.endpoint %}
<a class="{{ 'active' if ep == 'main.about' }}">Обо мне</a>
```
`request.endpoint` — имя текущей страницы. Если совпадает, ссылка получает класс `active`.

### 6.5. Безопасность: фильтр `| safe`
Jinja2 по умолчанию **экранирует** HTML, чтобы нельзя было внедрить вредный код (XSS).
`| safe` отключает экранирование. Мы используем его **только** для HTML, полученного из
нашего Markdown (`description_html`, `post.html`). Для данных от посетителей так делать нельзя.

## Шаг 7. Дизайн: золото на тёмно-синем

### 7.1. Палитра в CSS-переменных
В начале `style.css`:

```css
:root {
  --navy-900: #060d1c;   /* самый тёмный — подвал, блоки кода */
  --navy-800: #0a1428;   /* основной фон */
  --navy-700: #111f3d;   /* карточки */
  --navy-600: #1a2d55;   /* рамки */
  --gold-300: #f5dc8c;   /* светлое золото — заголовки, ховеры */
  --gold-500: #d4af37;   /* классическое золото */
  --gold-700: #9c7a1c;   /* тёмное золото — тени, рамки */
  --gold-gradient: linear-gradient(135deg, var(--gold-300), var(--gold-500) 45%, var(--gold-700));
}
```

Цвета используются через `var(--gold-500)`. Чтобы поменять тему, достаточно изменить эти строки.

### 7.2. Эффект «металлического золота»
Одного жёлтого цвета мало: золото выглядит как золото благодаря **переходу от светлого к тёмному**.
Поэтому кнопки, логотип и аватар закрашены градиентом `--gold-gradient`.

Золотой текст — градиент, «вырезанный» по буквам:
```css
.gold-text {
  background: var(--gold-gradient);
  -webkit-background-clip: text;
  background-clip: text;
  color: transparent;
}
```

### 7.3. Глубина фона
Фон — не плоский цвет, а наложение мягких радиальных градиентов: тёплое золотое свечение
справа сверху и синее слева. Отсюда ощущение «дорогого» тёмного сайта.

### 7.4. Шрифты
- **Cinzel** — заголовки и логотип (классический, «римский» вид, подходит к золоту);
- **Inter** — основной текст (хорошо читается);
- **JetBrains Mono** — код.

Подключены из Google Fonts в `base.html`.

### 7.5. Адаптивность
- `.grid` с `repeat(auto-fill, minmax(290px, 1fr))` сам решает, сколько карточек помещается в ряд;
- `clamp(2.2rem, 6vw, 4rem)` — размер заголовка плавно меняется от ширины экрана;
- `@media (max-width: 720px)` — на телефоне меню прячется в «бургер».

### 7.6. Доступность
- `@media (prefers-reduced-motion: reduce)` отключает анимации тем, у кого это выбрано в системе;
- у картинок есть `alt`, у кнопки меню — `aria-label`.

## Шаг 8. JavaScript: меню, анимации, фильтр

Весь JS лежит в `main.js`, без библиотек.

**Бургер-меню:** по клику добавляем или убираем класс `open`, а CSS разворачивает список.

**Появление при прокрутке:** `IntersectionObserver` следит, когда элемент с классом `.reveal`
попадает в экран, и добавляет класс `visible`. CSS плавно проявляет его.

**Фильтр проектов:** у каждой карточки есть атрибут `data-tags="Python|Flask|..."`.
По клику на тег скрываем карточки, в которых этого тега нет:
```js
const show = filter === "*" || tags.includes(filter);
card.classList.toggle("hidden", !show);
```

## Шаг 10. SEO: sitemap, robots, мета-теги

- В `base.html` у каждой страницы свои `<title>` и `<meta name="description">` (через блоки).
- **Open Graph** (`og:title`, `og:description`) отвечает за красивое превью ссылки в Telegram и VK.
- `/sitemap.xml` генерируется автоматически из списка проектов и статей. Поисковик узнаёт обо всех страницах.
- `/robots.txt` разрешает индексацию и указывает на sitemap.

> Перед публикацией задайте реальный адрес сайта: переменная окружения `SITE_URL`.

## Шаг 12. Статическая сборка и публикация

### 12.1. Сборка
```bash
python freeze.py
```
Frozen-Flask обходит все страницы и сохраняет их в `build/` как обычные HTML-файлы.
Страницы с параметрами (`/projects/<slug>/`) он не может угадать сам, поэтому в `freeze.py` есть
**генераторы**, которые перечисляют все slug:

```python
@freezer.register_generator
def project():
    for p in get_projects():
        yield "main.project", {"slug": p["slug"]}
```

> 💡 **Ошибка, которая возникла при разработке:** сначала генератор возвращал только `{"slug": ...}`.
> Flask ответил `BuildError: Could not build url for endpoint 'project'`. Причина в том, что маршруты лежат
> в блюпринте `main`, поэтому полное имя — `main.project`. Решение: явно указать endpoint в `yield`.

### 12.2. Публикация на GitHub Pages (бесплатно)
1. Создайте репозиторий `Xagan6_9.github.io` на GitHub.
2. Загрузите проект:
   ```bash
   git init
   git add .
   git commit -m "Первая версия портфолио"
   git branch -M main
   git remote add origin https://github.com/<ваш-логин>/<ваш-логин>.github.io.git
   git push -u origin main
   ```
3. Создайте файл `.github/workflows/deploy.yml`:
   ```yaml
   name: Deploy
   on:
     push:
       branches: [main]
   permissions:
     contents: read
     pages: write
     id-token: write
   jobs:
     build:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: actions/setup-python@v5
           with: { python-version: "3.12" }
         - run: pip install -r requirements.txt
         - run: pytest
         - run: python freeze.py
           env:
             SITE_URL: https://<ваш-логин>.github.io
         - uses: actions/upload-pages-artifact@v3
           with: { path: build }
     deploy:
       needs: build
       runs-on: ubuntu-latest
       environment: github-pages
       steps:
         - uses: actions/deploy-pages@v4
   ```
4. На GitHub: **Settings → Pages → Source: GitHub Actions**.

Теперь каждый `git push` автоматически тестирует, собирает и публикует сайт.

### 12.3. Другие варианты
- **Netlify / Cloudflare Pages / Vercel** — перетащите папку `build/` в веб-интерфейс.
- **Render / PythonAnywhere** — если нужен «живой» Flask (например, для формы обратной связи).
  Команда запуска: `gunicorn "app:create_app()"` (добавьте `gunicorn` в requirements).

## Как менять сайт под себя (шпаргалка)

| Хочу… | Где менять |
|---|---|
| Поменять имя, подпись | `config.py` → `SITE_NAME`, `SITE_TAGLINE` |
| Поменять ссылки на соцсети | `config.py` → `SOCIAL` |
| Поменять навыки | `config.py` → `SKILLS` |
| Добавить проект | `content/projects.yaml` (скопировать блок) |
| Убрать проект с главной | `featured: false` |
| Написать статью | новый файл `content/posts/имя.md` |
| Поменять текст на главной | `app/templates/index.html` |
| Поменять «Обо мне» | `app/templates/about.html` |
| Поменять цвета | `app/static/css/style.css`, блок `:root` |
| Поменять шрифты | ссылка Google Fonts в `base.html` + `font-family` в CSS |
| Добавить новую страницу | функция в `routes.py` + шаблон + ссылка в меню `base.html` |

**Пример: новая страница «Резюме»**
1. В `routes.py`:
   ```python
   @bp.route("/resume/")
   def resume():
       return render_template("resume.html")
   ```
2. Создайте `app/templates/resume.html`:
   ```html
   {% extends "base.html" %}
   {% block content %}<h1>Резюме</h1>{% endblock %}
   ```
3. Добавьте пункт в меню в `base.html`:
   ```html
   <li><a href="{{ url_for('main.resume') }}">Резюме</a></li>
   ```

## Частые ошибки и решения

| Ошибка | Причина | Решение |
|---|---|---|
| `'python' не является командой` | Python не установлен или не в PATH | переустановить Python с галочкой «Add to PATH» |
| `ModuleNotFoundError: flask` | не активировано окружение | `.venv\Scripts\activate` |
| Скрипт активации запрещён (PowerShell) | политика выполнения | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` или используйте `cmd` |
| Изменения в YAML/статьях не видны | кэш `lru_cache` | перезапустить сервер |
| `yaml.scanner.ScannerError` | ошибка отступов в YAML | проверить пробелы, не использовать Tab |
| `TemplateNotFound` | опечатка в имени шаблона | имя файла в `templates/` должно совпадать |
| `BuildError ... Did you mean 'main.xxx'` | забыт префикс блюпринта | писать `url_for('main.xxx')` |
| Стили не обновились | кэш браузера | Ctrl+F5 |
| Порт 5000 занят | запущен другой сервер | закрыть его или `app.run(port=5001)` |
